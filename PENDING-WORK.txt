PRINTER CARE - RELEASE VALIDATION

Maintenance-only scope, public beta 0.9.0-beta.1.

Completed on the G7020:
1. Panel error cleared; printer returned to Ready after both check prints.
2. Nozzle and alignment-value pages printed and photographed. No obvious missing
   nozzle lines, white streaks or missing colors are visible at photo resolution.
3. A complete held one-page job in the Canon Windows queue was canceled. Reused
   or changed identity was rejected. No page was sent to the physical printer.
4. Extracted portable startup, native export and upgrade data preservation passed.
5. Automatic printhead alignment completed through the native interface in about
   4 minutes 19 seconds. The printer saved changes to seven adjustment values.
6. Fresh Windows Sandbox passed offline portable startup, read-only native USB
   and queue helpers, and missing-helper handling without development tools.
   Native UI inspection verified both themes, device-theme following, offline
   controls, experimental warnings and sample report export. Zero printer writes.

Remaining validation:
1. Physical in-flight IPP job cancellation when a suitable test job exists.

The native nonzero waste-counter clear and printer-side in-flight cancellation
are labeled Experimental, with a separate acknowledgment before dispatch.
The clean Windows test kit automates startup and read-only helper checks in an
actual fresh system; a development-host pass does not count as clean Windows.

The alignment-value print is a check. Automatic alignment is a separate action
that uses two sheets from the front cassette and stores its adjustment.
The initial photograph alone did not certify calibration. The separate automatic
alignment cycle has since completed; ordinary print quality was not photographed
again after calibration.

The waste counter is already zero. Do not create another reset merely for testing.
Original protocol reset succeeded; native diagnostics and rejection guards were
hardware verified. Nonzero native clear remains untested and is documented.

Scanning and document workflows are removed from the supported scope. The prior
scan attempt aborted with JobCanceledAtDevice and was followed by DeviceBusy /
D107. Remote UI called this an operator error without a specific support code.
The panel error has since been cleared manually. The utility does not attempt
remote recovery or repeat that scan.

EEPROM backup, additional absorber groups, unverified model writes, macOS and
Android are outside this release. No automatic driver changes or firmware writes.
