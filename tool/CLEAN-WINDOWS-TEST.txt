PIXMA FIXA - CLEAN WINDOWS TEST KIT

Use a fresh Windows 11 x64 virtual machine, Windows Sandbox, or a separate clean
Windows PC. No Flutter, Dart, Python, development tools or printer drivers should
be installed for this test. Keep Windows security protections enabled.

The scripts only start the app and list native interfaces/queues. They never
print, clean, reset, scan, alter a driver or modify a Windows optional feature.
They use isolated temporary data and a restricted child-process PATH.

WINDOWS SANDBOX
Windows Sandbox must already be installed and hardware virtualization available.
Installing it can require administrator access and a restart. This kit does not
enable features, change firmware settings or restart the host.

From PowerShell, prepare a private configuration with these scripts:
  ./New-SandboxTest.ps1 -PackageZip ./PixmaFixa-Windows-VERSION.zip -OutputDirectory ./PrivateSandboxTest
Open PrivateSandboxTest/PixmaFixa-test.wsb. The test runs automatically offline
with printer, camera, audio and clipboard redirection disabled. Only the test input
and a dedicated results folder are mapped; the input is read-only.
The PowerShell execution-policy flag applies only to the test process inside the
disposable guest. It does not change the host's execution policy.
Read PrivateSandboxTest/results/result.json after completion. The app opens for
the manual theme, layout and save-dialog checks. Close Sandbox when finished.
Generated .wsb files contain local paths and should not be published.

SEPARATE CLEAN PC OR VM
Copy the Windows ZIP and these scripts to the clean system. In PowerShell run:
  ./Invoke-CleanWindowsTest.ps1 -PackageZip ./PixmaFixa-Windows-VERSION.zip -OutputPath ./result.json -ConfirmCleanMachine
Add -ShowApplication to inspect the app after the automatic checks.
Use -ConfirmCleanMachine only on a fresh test system. If a downloaded script is
blocked, review its source and your local script policy rather than disabling
Windows security protections. The Sandbox route runs the reviewed test script
under its own temporary process policy.

WHAT THE RESULT MEANS
portableChecksPassed records successful extracted startup, working directory and
PATH isolation, read-only native helper responses and missing-helper handling.
cleanWindowsPassed also requires the clean-system confirmation and no detected
development tools. A pass on a development host never counts as a clean-system
pass. The runner cannot prove a machine's provenance; use an actual fresh system.
The JSON report omits usernames, printer identifiers, addresses and raw exchanges.
Manual checks still needed: native save dialog, theme choices, and readable UI
at 100% and 150% display scaling. This kit does not test hardware maintenance.
